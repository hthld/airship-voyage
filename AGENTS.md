# Airship Voyage — общие правила для ассистентов (Claude Code, Codex)

Мод для Minecraft Java 1.21.1 / NeoForge 21.1.172 (Java 21, ModDevGradle): исторические жёсткие дирижабли
1:1 с реалистичной физикой, строительством, повреждениями и крушениями. Полное ТЗ — `docs/GDD_v0.1.md`
(читать нужные разделы, особенно 25.2 и 26). **Общение с владельцем — по-русски.**

## 1. Восстановление после очистки контекста или в новом чате

1. Прочитать этот файл целиком.
2. Прочитать `docs/HANDOFF.md` — текущее состояние, активная задача, следующий шаг.
3. Найти активную задачу в `docs/TASKS.md` (по ID из HANDOFF).
4. **Сверить передачу с Git и исходниками** — передача может отставать:
   ```bash
   git log --oneline -5
   git status --short
   git diff --stat
   ```
   Базовый коммит и список незавершённых изменений в HANDOFF должны совпадать с тем, что показывает Git;
   упомянутые классы и тесты — существовать в исходниках. Если расходится — верить Git и коду, сказать владельцу
   и поправить HANDOFF.
5. Подробности — по ссылкам и по необходимости: `docs/ARCHITECTURE.md` (устройство), `docs/DECISIONS.md`
   (решения и причины), `docs/reviews/` (аудиты и ответы), `docs/sessions/` (история), `README.md` (команды игры).

Цифры «тесты прошли» в документах — это результат на момент записи. Перед тем как на них опираться,
перезапустить проверки (раздел 4).

## 2. Роли

| Кто | Что делает |
|---|---|
| **Владелец** | ставит задачи, проверяет мод в игре, даёт разрешения (раздел 3), пересылает ревью |
| **Claude Code** | реализует изменения: код, тесты, документация, сборка, jar для лаунчера |
| **Codex** | по умолчанию — **ревью только на чтение**: не меняет файлы репозитория, не коммитит, не пушит, не запускает команды, которые пишут в проект (Gradle пишет в `build/`) — если владелец не разрешил явно. Писать — только по прямому поручению владельца |
| GPT (через владельца) | внешнее ревью только на чтение — по тем же правилам, что Codex |

**Формат ревью (Codex, GPT):** нумерованные замечания — серьёзность, файл и строка/метод, что не так, конкретный
сценарий или тест, предлагаемое исправление, уверенность. Предположения отмечать как предположения.

**Обработка ревью (Claude):** сохранить текст в `docs/reviews/AUD-NN.md` (замечания — `AUD-NN-01`, `AUD-NN-02`, …;
если полного текста нет — так и написать), каждое замечание проверить по коду и исходникам Minecraft, не принимать
на веру. Ответ по ID: «AUD-NN-MM — принято, исправлено (тест X)» или «AUD-NN-MM — отклонено, потому что…».
Завести задачи в `docs/TASKS.md`. Тест на подтверждённую ошибку должен падать без исправления — проверить откатом.

## 3. Разрешения владельца (действуют всегда)

- **Коммит и пуш — только после явного разрешения владельца, каждый раз.** Разрешение на один коммит не переносится
  на следующий. Пуша пока не было и удалённого репозитория нет.
- **Ничего не удалять без подтверждения** (файлы проекта, миры, файлы в `minecraft files/`). Исключение — постоянное
  поручение ниже: свежий jar мода заменяет прежний jar с тем же именем в папке модов лаунчера.
- После каждого завершённого шага: собрать jar и положить его в `minecraft files/1.21.1-launcher/mods/` —
  владелец запускает мод из обычного лаунчера (NeoForge 21.1.172). Это делается без отдельного вопроса.
- Установка программ в систему, изменения вне папки проекта, публикация и обращения к внешним сервисам —
  только с согласия владельца.
- Личные данные владельца (почта и т.п.) в код, документы и запросы наружу не записывать; автор коммитов задан
  самим владельцем в настройках Git.

## 4. Сборка и проверка

| Команда | Что делает |
|---|---|
| `gradlew.bat test` | unit-тесты ядра `core` (секунды) |
| `gradlew.bat runGameTestServer` | игровые тесты на настоящем сервере (~1 мин), должно быть «All N required tests passed» |
| `gradlew.bat build` | jar в `build/libs/airshipvoyage-0.0.1-proto.jar` |
| `gradlew.bat runClient` | игра с модом (проверку глазами делает владелец) |

Число unit-тестов — по XML в `build/test-results/test/`. Строки `[test] …` в логе игровых тестов — фактические
числа для сверки с ручным расчётом.

Окружение: Windows 11, JDK Temurin 21, IntelliJ IDEA, Git for Windows (`C:\Program Files\Git\cmd\git.exe`).
Проект: `C:\Minecraft Files\Airship Voyage`. Исходники Minecraft/NeoForge для сверки API:
`build/moddev/artifacts/neoforge-21.1.172-sources.jar`.

## 5. Правила разработки

- **`com.airshipvoyage.core` не импортирует `net.minecraft.*`, `net.neoforged.*`, JOML.** Вся физика и логика,
  которую можно посчитать без игры, — там и покрыта unit-тестами. Игровые классы только переводят мир в вызовы ядра.
- Без внешних физических движков и без Create / Valkyrien Skies (ТЗ 22.1). Сервер — источник истины, клиент интерполирует.
- Каждое изменение физики подтверждать тестом **и сверять числа с ручным расчётом** — тест, который проходит
  с первого раза, перепроверять выводом реальных значений. Новый тест на найденную ошибку должен падать без исправления.
- Игровые тесты (`debug/AirshipGameTests`): шаблон `ship_dock` 28×22×28; фазы отсчитывать по `ship.tickCount`
  (`onShipTicks`), а не по часам теста; корабль должен целиком помещаться в зону и не долетать до барьерных стен.
- API Minecraft/NeoForge проверять по исходникам, не по памяти.
- Комментарии и документация — по-русски, со ссылками на разделы ТЗ.
- Известные ловушки, на которые уже наступали, — `docs/sessions/2026-11-09-01-claude-ai-chat.md`
  («Ошибки, найденные тестами») и разделы «Найдено» в `docs/ARCHITECTURE.md`.

## 6. Память проекта: какие файлы за что отвечают

| Файл | Содержание | Когда обновлять |
|---|---|---|
| `docs/HANDOFF.md` | **краткая** передача: дата, ветка, базовый коммит, активная задача, сделанное, проверки, незавершённые изменения, следующий конкретный шаг | после каждого важного результата (шаг готов, проверки прошли/упали, коммит, ответ на ревью) и **перед очисткой контекста** |
| `docs/TASKS.md` | задачи с постоянными ID и статусами | при появлении задачи и смене статуса |
| `docs/DECISIONS.md` | решения и причины; утверждённые отдельно от предложений | при принятии или отклонении решения |
| `docs/ARCHITECTURE.md` | описание **текущего** устройства, найденное, ограничения | после шага, изменившего устройство |
| `docs/reviews/AUD-NN.md` | тексты аудитов и ответы по ID | при получении ревью и ответе |
| `docs/sessions/ГГГГ-ММ-ДД-NN-тема.md` | история: записи завершённых этапов и промежуточных передач | по завершении этапа и при промежуточной передаче |
| `README.md` | статус, как играть, команды `/airship`, структура | после шага, изменившего поведение или команды |

Правила записи: факты отделять от предположений — непроверенное помечать «не проверено» / «предположение».
Указывать, чем проверено (команда, тест, число). Историю не переписывать: новые этапы — новыми файлами в `docs/sessions/`.
ID задач и замечаний не переиспользовать.
