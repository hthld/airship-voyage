# Airship Voyage — инструкции для Claude

Мод для Minecraft Java 1.21.1 / NeoForge 21.1.172 (Java 21, ModDevGradle): исторические жёсткие дирижабли
1:1 с реалистичной физикой, строительством, повреждениями и крушениями. Общение с владельцем — по-русски.

## Прочитать в начале работы

1. `docs/HANDOFF.md` — что уже сделано, какие решения приняты и почему, что найдено тестами, как работаем.
2. `README.md` — статус, структура, команды `/airship`, план прототипа.
3. `docs/ARCHITECTURE.md` — архитектура по шагам, ограничения, **план следующего шага (раздел 12)**.
4. `docs/GDD_v0.1.md` — полное ТЗ (большое; читать нужные разделы, особенно 25.2 и 26).

## Сборка и проверка

| Команда | Что делает |
|---|---|
| `gradlew.bat test` | unit-тесты ядра `core` (секунды) |
| `gradlew.bat runGameTestServer` | игровые тесты на настоящем сервере (~1 мин), должно быть «All N required tests passed» |
| `gradlew.bat build` | jar в `build/libs/` |
| `gradlew.bat runClient` | игра с модом (проверку глазами делает владелец) |

После каждого завершённого шага: собрать jar и положить его в
`minecraft files/1.21.1-launcher/mods/` — владелец запускает мод из обычного лаунчера (NeoForge 21.1.172).

## Правила

- **`com.airshipvoyage.core` не импортирует `net.minecraft.*`, `net.neoforged.*`, JOML.** Вся физика и логика,
  которую можно посчитать без игры, — там и покрыта unit-тестами. Игровые классы только переводят мир в вызовы ядра.
- Без внешних физических движков и без Create / Valkyrien Skies (ТЗ 22.1). Сервер — источник истины, клиент интерполирует.
- Каждое изменение физики подтверждать тестом **и сверять числа с ручным расчётом** — тест, который проходит
  с первого раза, перепроверять выводом реальных значений. Новый тест на найденную ошибку должен падать без исправления.
- Игровые тесты (`debug/AirshipGameTests`): шаблон `ship_dock` 28×22×28; фазы отсчитывать по `ship.tickCount`
  (`onShipTicks`), а не по часам теста; корабль должен целиком помещаться в зону и не долетать до барьерных стен.
- API Minecraft/NeoForge проверять по исходникам (`build/moddev/artifacts/neoforge-21.1.172-sources.jar`), не по памяти.
- Комментарии и документация — по-русски, со ссылками на разделы ТЗ. После шага обновлять README (статус,
  команды) и ARCHITECTURE (что сделано, что найдено, ограничения, план следующего шага).
- Перед коммитом/пушем спрашивать владельца. Ничего не удалять без подтверждения.

## Ревью от GPT

Владелец иногда присылает ревью от GPT (она только читает код). Каждое замечание проверить по коду, не принимать
на веру. Ответить по номерам: «N — принято, исправлено (тест X)» или «N — отклонено, потому что…» — владелец
пересылает ответ обратно.
